# 예상 혼잡 입력 파일 (FR-008, API-012)

이 디렉터리는 예상 혼잡 계산의 **운영 입력 위치**다. 백엔드는 앱 시작 시 아래 정규화 CSV 4개를 읽고,
요청마다 메모리에서 계산한다(요청이 공공 API 를 부르지 않는다). 위치는 환경변수 `CROWD_DATA_DIR` 로, 설정 파일(`data/seed/crowd/crowd_config.json`)은 `CROWD_CONFIG_PATH` 로 바꿀 수 있다.

- **실제 공공데이터 파일만 둔다.** 지금 있는 파일과 만든 방법(2026-11-27):
  - `metro_hourly.csv`: 부산교통공사_시간대별 승하차인원(공공데이터포털 파일 3057229, 2026-10-31 갱신본)의 2026-10.
    `uv run python -m app.modules.crowd.importers metro <원본 CSV>` (원본은 `data/crowd/raw/`, 커밋하지 않음)
  - `living_population.csv`: 부산광역시_일평균 생활인구수(행정동·시간, 통신사)(공공데이터포털 API 15164444,
    `getDongPopTime`)의 2026-09. `uv run python -m app.modules.crowd.importers living --month 202609`
    (`DATA04_SERVICE_KEY` 필요). 원본에 평일/주말 구분이 없어 같은 월 일평균을 WEEKDAY·WEEKEND 에 똑같이 쓴다.
    그래서 이 신호만으로는 평일과 주말 혼잡이 같다. population 은 주거 + 직장 + 방문 인구 합이다.
  - `place_signal_links.csv`: `data/samples` 의 10곳. DATA-04 는 장소 좌표의 행정동(카카오 좌표→행정구역 변환으로 찾고
    DATA-04 코드 목록에 있는지 확인), DATA-05 는 직선 800m 안의 가장 가까운 부산교통공사 역(동해선 등 다른 운영사 제외).
    역이 가까운 곳은 광안리해수욕장(광안)·용두산 공원(남포)·부산시립미술관(벡스코) 3곳뿐이라 이 3곳만 신뢰도 '중간',
    나머지는 '낮음'이다(혼잡 회피는 '중간' 이상만 쓴다).
  - `crowd_multipliers.csv`(날짜 배수 M)는 아직 없다.
- 시험용 가짜 표본은 `backend/tests/fixtures/crowd/` 에만 있다. 여기로 복사하지 않는다.
- 파일이 없으면 그 신호는 없는 것으로 본다. 깨진 행은 건너뛰고 건수만 경고 로그로 남긴다. 값을 지어내지 않는다.
- UTF-8(BOM 허용), 첫 줄은 머리줄. `#` 로 시작하는 줄은 주석으로 보고 건너뛴다.
- 원본(공공데이터 포털·부산시·부산교통공사 내려받기 파일)의 열 구성은 아래와 다를 수 있다. 원본 → 정규화 변환은 파일을 확보한 뒤 별도로 한다.
- 재배포 시 각 원본의 이용 조건(공공누리 유형 등)과 출처 표기를 따른다. 화면에는 `sources`·`signals` 로 출처를 보여 준다.

## 계산 요약

`score(p, d, h) = B × M × R`

- **B**(1단계): 장소에 연결된 신호(DATA-04 생활인구, DATA-05 도시철도 승하차)를 신호마다 자기 평균(그 기준 월의 모든 평일·주말×시간대)으로 나눈 상대값의 가중 평균. 신호마다 가장 최근 기준 월을 쓴다.
- **M**(2단계): `crowd_multipliers.csv` 의 (방문일, 장소의 구·군) 배수. 없으면 곱하지 않는다(대체 상수 없음).
- **R**(3단계, DATA-08): P0 에서는 곱하지 않는다.
- **등급**: 방문일 점수 `B(방문일의 평일/주말, h) × M(방문일)`(M 이 없으면 B)을 장소별 **기준 분포** 안의 백분위(중간 순위)로 바꾼다. 기준 분포는 언제나 M 을 곱하지 않은 B 의 모든 평일·주말×시간대 값이다(M 행이 생기거나 없어져도 기준이 흔들리지 않는다). 그래서 M>1 이면 그날이 더 붐비게, M<1 이면 더 한산하게 나오고, 기준 최댓값보다 크면 백분위 1.0 이다. 경계는 `data/seed/crowd/crowd_config.json` 의 `grade_percentiles`(기본 0.4/0.7/0.9) → 여유/보통/붐빔/매우 붐빔. 응답 `score` 는 이 백분위(0~1)다.
- **신뢰도**: 실제로 쓰인 서로 다른 근거 소스 수(DATA-04, DATA-05, M). 1단계 신호는 방문일의 평일/주말 행이 하나라도 있을 때만 센다(근거 보기·출처·기준 시각도 같다). 3개 이상 높음, 2개 중간, 1개 낮음, 0개면 '없음'에 시간대 목록이 비어 있다(화면 '정보 부족').
- **기준 시각(asOf)**: 쓰인 소스 기준 시각 중 가장 늦은 값. 월 자료는 그 달 1일 00:00(KST), M 은 `computed_at`.
- 평일/주말만 나눈다. 공휴일은 다루지 않는다(입력 자료 없음).

## 파일 형식

### `living_population.csv` — DATA-04 행정동 생활인구(시간대), 부산시 공공데이터

| 열 | 형식 | 설명 |
| --- | --- | --- |
| `ref_month` | `YYYY-MM` | 기준 월 |
| `adm_dong_code` | 문자열 | 행정동 코드 |
| `day_type` | `WEEKDAY` \| `WEEKEND` | 평일/주말 |
| `hour` | 0~23 | 시간대(시) |
| `population` | 0 이상 숫자 | 그 시간대의 월 일평균 생활인구 |

### `metro_hourly.csv` — DATA-05 도시철도 시간대별 승하차, 부산교통공사

| 열 | 형식 | 설명 |
| --- | --- | --- |
| `ref_month` | `YYYY-MM` | 기준 월 |
| `station_code` | 문자열 | 역 코드 |
| `station_name` | 문자열 | 역 이름(근거 보기 표시용, 비어도 됨) |
| `day_type` | `WEEKDAY` \| `WEEKEND` | 평일/주말 |
| `hour` | 0~23 | 시간대(시) |
| `boardings` | 0 이상 숫자 | 승차 인원 |
| `alightings` | 0 이상 숫자 | 하차 인원 |

값은 `boardings + alightings` 를 쓴다.

### `crowd_multipliers.csv` — 날짜 배수 M (DATA-06 지역별 방문자수·DATA-07 관광지 집중률에서 추정)

| 열 | 형식 | 설명 |
| --- | --- | --- |
| `date` | `YYYY-MM-DD` | 날짜 |
| `region` | 문자열 | 부산 구·군 이름. 장소 주소의 구·군과 같아야 한다. 예: `영도구`, `기장군` |
| `multiplier` | 0 보다 큰 숫자 | 날짜 배수 |
| `source` | `DATA-06` \| `DATA-07` | 추정에 쓴 자료 코드. 그 밖의 값은 건너뛴다 |
| `computed_at` | ISO 8601 일시 | 계산 시각. 시간대가 없으면 KST 로 본다 |

같은 (`date`, `region`) 은 한 행만 둔다(뒤 행은 건너뛴다).

이 파일은 손으로 만들지 않고 배치 잡 `data06`·`data07` 이 만든다(켜는 법: [`backend/README.md`](../../backend/README.md) '날짜 배수 M 수집').
지금은 키·지역 코드가 없어 두 잡이 꺼져 있고, 그래서 파일이 없다.

- M(d, 구·군) = 값(d) ÷ 같은 구·군·같은 평일/주말의 기간 평균. 대체 상수는 없다.
  - `DATA-06`(과거 날짜): 값 = 그날 방문자수(방문자 구분 합). 기간 = 최근 `DATA06_BASELINE_DAYS`(28)일
    (오늘 KST − `DATA06_LAG_DAYS`(3)일까지).
  - `DATA-07`(미래 날짜): 값 = 그날 그 구·군 관광지 집중률 평균. 기간 = 받은 예측 30일.
- 미래 날짜의 M 은 `DATA-07` 예측이 있을 때만 생긴다. 예측이 없는 날·구·군(응답에 그 구·군 관광지가 없음 포함)은 행이
  없고, 그날은 M 을 곱하지 않으며 신호로도 세지 않는다. `DATA-06` 은 과거 자료라 미래 날짜 행을 만들지 않는다.
- 값이나 평균이 0 이면 행을 만들지 않는다. 공휴일은 평일로 센다(파일 제공자와 같다, spec A-9).
- 항목 값이 틀려 거절된 (날짜, 구·군)은 계산에서 뺀다(합·평균이 줄어든 값을 쓰지 않는다). DATA-06 은 방문자 구분
  1·2·3(현지인·외지인·외국인으로 가정, 명세 확인 필요)이 하나씩 다 있어야 그날 합을 쓴다.
- 항목이 왔는데 쓸 수 있는 행이 하나도 없으면(필드 이름·코드 형식이 명세와 다름) 그 실행은 FAILED + 알림이고 파일은 그대로다.
  DATA-06 은 쓸 수 있는 과거 자료가 하나도 없어도 FAILED 다. DATA-06 실행의 `as_of` 는 실제로 쓴 가장 늦은 자료일이다.
- DATA-07 을 쓸 때 오늘(KST) 이후의 DATA-07 행은 모두 새 예측으로 바꾼다(새 예측에 없는 날·대응표에서 빠진 구·군의 옛 예측은 지운다).
  단, 모든 구·군 응답이 비면 코드(areaCd·signguCd)가 틀렸을 수 있어 `DATA-07 all regions empty` 로 FAILED + 알림이고
  파일은 그대로다. 일부 구·군만 비면 SUCCESS 이고 빈 구·군 수를 `data07_empty_regions` 경고 로그로 남긴다.
- 두 소스 모두 오늘에서 `CROWD_MULTIPLIER_RETENTION_DAYS`(365)일보다 오래된 자기 행은 쓸 때 지운다.
- `region` 은 응답의 시군구 코드를 [`data/seed/crowd/busan_region_codes.csv`](../seed/crowd/busan_region_codes.csv)
  (부산 16개 구·군)로 바꾼 이름이다. 표에 없는 코드(부산 밖)는 버린다. **TODO: 이 표의 코드 칸은 아직 비어 있다.**
  실제 응답·활용가이드 코드 첨부·행정표준코드(code.go.kr)로 확인한 값만 채운다.
- 쓰기는 임시 파일 → rename 이다. 수집 실패·중단이면 기존 파일이 그대로 남는다. 같은 (`date`, `region`) 은 나중 실행이
  덮어쓰고, 나머지 행(다른 소스·지난 날짜)은 남는다. `computed_at` 은 쓰기 시각(KST)이다.
- 읽기·합치기·바꾸기 동안 옆 잠금 파일 `.crowd_multipliers.csv.lock` 에 `fcntl.flock` 배타 잠금을 잡는다(POSIX 전용).
  data06·data07 이나 CLI `run` 과 `loop` 가 겹쳐도 한쪽 결과를 잃지 않는다.
- 파일 교체는 DB 커밋(ingestion_runs SUCCESS)보다 먼저 일어난다. 커밋이 실패하면 파일이 실행 기록보다 새것일 수 있다(허용).

### `place_signal_links.csv` — 장소 → 1단계 신호 연결

| 열 | 형식 | 설명 |
| --- | --- | --- |
| `place_id` | 문자열 | 공공 장소 ID(TourAPI contentid) |
| `signal` | `DATA-04` \| `DATA-05` | 신호 |
| `key` | 문자열 | DATA-04 는 행정동 코드, DATA-05 는 역 코드 |
| `note` | 문자열 | 연결 근거 메모(예: 도보 거리) |

연결이 없는 장소는 정보 부족이다.
