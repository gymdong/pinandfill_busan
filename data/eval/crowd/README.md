# AC-009 혼잡 추정 검증 입력

AC-009: 영도구 공공 와이파이 3곳(흰여울문화마을·봉래물양장·감지해변)의 방문자 순위와 우리 추정의
Spearman ρ ≥ 0.5, 그리고 팀 현장 관측 30건과의 등급 일치율 ≥ 70%.

이 디렉터리에는 양식(머리줄만)만 있다. 값은 팀이 채우며, 지어낸 값을 커밋하지 않는다.
채운 파일은 공유 저장소에 올리기 전에 와이파이 자료의 이용 조건을 확인한다. 아래 명령은 어느 경로의 파일이든 읽는다.

## 먼저 할 일

- `place_id` 는 places 의 id(공공 contentid)다. 봉래물양장·감지해변은 아직 places 에 없을 수 있으니
  먼저 등록하고 그 id 를 쓴다.
- 검증 대상 장소는 `--places <id> <id> <id>` 로 지정한다. 지정하지 않으면 `data/samples/places_sample.csv` 에서
  이름(흰여울문화마을·봉래물양장·감지해변)으로 찾은 id 를 쓰고, 셋 중 하나라도 표본에 없으면 입력 오류(종료 코드 3)가
  되므로 그때는 `--places` 가 필수다. 지정한 장소 밖의 행은 계산에서 빠진다.
- 장소마다 혼잡 입력 신호가 연결돼 있어야 추정이 나온다(`data/crowd/place_signal_links.csv`).
  연결이 없으면 그 행은 "정보 부족"으로 따로 집계되고 불일치로 세지 않는다.

## 현장 관측 `observations_template.csv`

| 열 | 내용 |
| --- | --- |
| `place_id` | 장소 id |
| `date` | 관측 날짜 `YYYY-MM-DD`(필수) |
| `hour` | 관측 시각의 시(0~23 정수, 필수) |
| `observed_grade` | `여유` / `보통` / `붐빔` / `매우 붐빔` 중 하나(필수) |
| `observer` | 관측한 팀원 |
| `note` | 메모(날씨·행사 등) |

30건 이상 채운다. 장소 3곳·평일/주말·여러 시간대에 고르게 나눈다. 같은 판단 기준(체감 혼잡)으로 기록한다.
형식이 틀린 행은 거절 목록에 나온다.

## 와이파이 방문자 `wifi_visitors_template.csv`

| 열 | 내용 |
| --- | --- |
| `place_id` | 장소 id |
| `date` | 날짜 `YYYY-MM-DD`. 비워도 된다 |
| `hour` | 시(0~23). 비워도 된다 |
| `visitors` | 방문자수(0 이상 숫자) |

date·hour 가 빈 행의 처리:

- 장소 안 시간대별 ρ 는 date 와 hour 가 모두 있는 행만 쓴다. 우리 점수가 장소별 백분위라 장소끼리는 비교할 수 없기 때문이다.
  같은 (장소, date, hour) 가 여러 행이면 평균한다.
- 비어 있는 행은 ρ 에서 빠지고 "날짜·시각이 비어 뺀 행" 으로 건수만 출력된다. 장소 단위 합계만 있는 자료로는
  ρ 를 계산하지 못한다.
- 장소 간 ρ(원점수 B×M 비교)는 공급자가 원점수를 내놓지 않아 계산하지 않는다.
- 장소마다 (날짜, 시각) 쌍이 5개 이상이어야 그 장소의 ρ 를 낸다. ρ 를 낸 장소가 3곳 미만이면 통과로 판정하지 않는다.

## 실행

`backend/` 에서:

```bash
uv run python -m app.modules.crowd.validation \
  --places <id1> <id2> <id3> \
  --observations ../data/eval/crowd/observations.csv \
  --wifi ../data/eval/crowd/wifi_visitors.csv
```

혼잡 입력은 기본 `data/crowd/`(`--crowd-dir`, 환경변수 `CROWD_DATA_DIR`), 설정은 `data/seed/crowd/crowd_config.json`
(`--config`, `CROWD_CONFIG_PATH`)을 쓴다. 장소 주소의 구·군(표본 장소 기준)으로 날짜 배수 M 도 운영 API 와
같은 방식으로 적용한다.

표본 크기 기준은 옵션으로 바꿀 수 있다: `--min-observations`(기본 30), `--min-places`(기본 3), `--min-points`(기본 5).
시험·예행연습용이고, 최종 판정은 기본값으로 한다.

## 판정 규칙

- ρ: 장소별 ρ 의 평균이 0.5 이상이고, ρ 를 낸 모든 장소가 0 이상이어야 한다. 평균만 보면 한 장소의 음의 상관(추정이
  거꾸로 간다)을 다른 장소가 가려 통과할 수 있어서다. 출력에 장소별 ρ, 평균, 최소를 모두 보인다.
- 일치율: 정보 부족(추정이 없어 비교하지 못한 관측)을 불일치로 센 엄격한 일치율이 70% 이상이어야 한다. 정보 부족을
  빼고 계산한 일치율은 참고로만 출력한다. 정보 부족이 많으면 일치율이 부풀려지기 때문이다.
- 관측이 30건 미만이거나 ρ 를 낸 장소가 3곳 미만이면 통과를 주장하지 않는다(판정 불가).
- `--places` 밖 장소의 행은 계산에서 빼되 관측·와이파이 따로 place_id 와 행 수를 출력한다. 표본에도 `--places` 에도 없는
  place_id(오타 의심)가 관측에 있으면 일치율이 부풀려졌을 수 있어 종합을 판정 불가(종료 코드 2)로 한다.
- `--min-*` 옵션은 1 이상이어야 한다(아니면 종료 코드 3).

## 종료 코드

| 코드 | 뜻 |
| --- | --- |
| 0 | 통과 |
| 1 | 미달(기준 하나 이상 미충족) |
| 2 | 판정 불가(관측·장소 수 부족 등) |
| 3 | 입력 오류(파일 없음, 머리줄의 없는/모르는 열, 잘못된 옵션 등). 메시지는 표준 오류로 나온다 |

머리줄 오류는 전체를 멈추고, 행 오류(열 개수 불일치, 형식 오류 등)는 실제 파일 줄 번호와 사유와 함께 거절 목록에 나온다.
출력: 장소별 ρ 와 평균·최소, 등급 일치율(엄격·참고), 정보 부족 건수, 짝을 못 지은 행, 종합 판정.
