# 시연 시나리오 (12/1 최종 발표, 녹화)

시연은 실시간이 아니라 핵심 시나리오 하나를 녹화해 보여 준다(PM 결정, 2026-11-27). 이 문서는 녹화 순서와 화면에서 보일 값, 말할 문장을 정한다.
아래 값은 2026-11-28 dev(`9441f47` 이후)에서 실제 백엔드로 계산해 확인했다. 경로는 TMAP 무료 한도(하루 10건) 때문에 대부분 '추정' 이동시간이다.

## 보여 줄 것

| 순서 | 장면 | 요구사항 |
| --- | --- | --- |
| 1 | 한 줄로 여행 조건 입력 → 항목으로 채워짐 | FR-001·002 |
| 2 | 꼭 갈 곳 4곳 담기, 그중 3곳은 시간 고정 | FR-003 |
| 3 | 코스 만들기 → 고정 시각 그대로, 시간을 안 정한 용두산은 덜 붐비는 저녁으로 | FR-005·009, AC-010 |
| 4 | 구간 사이 경유지 추천 → 우회·혼잡 비교 → 넣기, 고정 시각 그대로 | FR-004·006, AC-005·003 |
| 5 | 장소 상세의 시간대별 예상 혼잡과 근거 | FR-008, AC-008 |
| 6 | 지도에서 일차 경로·마커, 목록과 동기화 | FR-007, AC-007 |
| 7 | 되돌리기 | FR-006, AC-006 |

## 시나리오 입력값

- 날짜: **2026-12-05 (토)** 당일, 하루 일정 **10:00–21:00**, 이동 **대중교통**
- 꼭 갈 곳(이 순서로 담는다):

| 장소(카카오 검색어) | 시간 |
| --- | --- |
| 태종대 → '태종대유원지' | 10:00–11:00 고정 |
| 광안리해수욕장 | 13:00–14:00 고정 |
| 용두산공원 | 시간 정하지 않음(1시간) |
| 부산시립미술관 | 17:00–18:00 고정 |

시간을 정하지 않은 용두산을 미술관보다 앞에 담는 것이 중요하다. 혼잡을 모르면 엔진은 광안리 뒤(14:45)에 넣는데,
토요일 14시대 용두산은 '예상 매우 붐빔'이라 혼잡 회피(FR-009)가 미술관 뒤 18:53으로 옮긴다.

## 녹화 전 준비

1. **최신 dev** 로 받는다(`git pull`). `data/crowd/` 에 생활인구·승하차·연결표 3개 파일이 있어야 한다.
2. **키**
   - `backend/.env`: `KAKAO_REST_API_KEY`(장소 검색, 필수). `TMAP_API_KEY`는 있어도 되고 없어도 된다(없거나 한도 초과면 '추정').
   - `frontend/.env.local`: `VITE_KAKAO_MAP_JS_KEY`(지도, 필수). 허용 도메인에 `http://localhost:5173`.
   - `GEMINI_API_KEY`는 없어도 된다. 한 줄 해석은 규칙으로, 경유지 이유는 규칙 문구로 나온다.
3. **서버**(녹화 중에 다시 켜지 않는다. `DATABASE_URL`이 없으면 여행이 메모리에만 있어 재시작하면 사라진다)

   ```bash
   cd backend && uv run uvicorn app.main:app --port 8000
   cd frontend && npm run dev            # http://localhost:5173
   ```

4. **브라우저**: Chrome 개발자 도구 기기 모드 **390 × 844**(휴대폰 세로). 이전 시도 흔적을 지우려면 사이트 데이터(localStorage)를 지운다.
5. 녹화 직전 한 번 끝까지 리허설한다. TMAP 키가 있으면 리허설에서 한도(10건)를 쓰므로, 녹화 때 '추정'으로 나와도 정상이다.

## 진행 순서와 대본

각 단계의 **화면**은 확인한 값이다. 이동시간은 '추정'이라 1~2분 다를 수 있다.

### 1. 여행 시작 (약 30초)

- 한 줄 입력에 `12/5 당일 대중교통` → **해석**. 날짜·이동이 채워진다.
- 하루 일정 끝을 **21:00** 으로 바꾼다.
- 대본: "여행 조건은 한 줄로 쓰면 항목으로 풀어 줍니다. 틀린 건 바로 고칠 수 있어요."

### 2. 꼭 갈 곳 담기 (약 45초)

- 장소 검색으로 위 표의 4곳을 순서대로 **담기**. 검색 결과의 '상세 정보 있음'·'영업시간 확인 필요' 배지를 짧게 보여 준다.
- 태종대유원지·광안리·미술관은 **시간 정하기** 로 시각을 넣는다. 용두산은 그대로 둔다.
- 대본: "꼭 가고 싶은 곳만 고릅니다. 시간을 정한 곳은 고정돼서 어떤 계산에서도 움직이지 않아요."

### 3. 코스 만들기 (약 40초)

- **코스 만들기**. 타임라인 화면:

| 시각 | 장소 | 카드 | 예상 혼잡 |
| --- | --- | --- | --- |
| 10:00–11:00 | 태종대유원지 🔒 | 실선 | 붐빔(신뢰 낮음) |
| 13:00–14:00 | 광안리해수욕장 🔒 | 실선 | 붐빔(신뢰 중간) |
| 17:00–18:00 | 부산시립미술관 🔒 | 실선 | 붐빔(신뢰 중간) |
| 18:53–19:53 | 용두산 공원 | 실선 | 붐빔(신뢰 중간) |

- 대본: "고정한 세 곳은 정한 시각 그대로예요. 시간을 정하지 않은 용두산은 광안리 다음 14시대에 넣을 수도 있었지만,
  토요일 그 시간은 예상 '매우 붐빔'이라 저녁으로 옮겼어요. 혼잡 신뢰도가 '중간' 이상일 때만 이렇게 옮깁니다."
- 이동시간 옆 `≈` 를 한 번 눌러 "추정 이동시간이에요. 경로 API 결과가 없어 직선거리로 계산했어요."를 펼쳐 보여 준다.
  대본: "경로 API를 못 쓰면 일정이 끊기지 않고 추정값으로 이어 가고, 추정이라고 표시합니다."

### 4. 경유지 추천 (약 50초)

- 태종대유원지와 광안리 사이 **사이에 들를 곳 추천받기** → 시트 제목 "태종대유원지 → 광안리해수욕장 사이".
- **우회는 최대 30분** 으로 바꾸면 후보 **오륙도 스카이워크 +14분 우회**, 예상 여유(신뢰 낮음), '넣어도 그대로: 광안리해수욕장 13:00, 부산시립미술관 17:00'.
- **넣기** → 알림 "일정에 넣었어요: 오륙도 스카이워크…", 점선 카드가 강조된다. 광안리 13:00 은 그대로다.
- 대본: "핵심지 사이 빈 시간을 우회가 적고 덜 붐비는 곳으로 채웁니다. 넣어도 고정한 시각은 바뀌지 않아요.
  직접 고른 곳은 실선, 추천으로 채운 곳은 점선이에요."

### 5. 장소 상세 (약 30초)

- 용두산 공원 카드의 **장소 상세 보기** → 시간대별 예상 혼잡(토요일 13–17시 '매우 붐빔', 19시 '보통'), 신뢰도 중간, 기준 시각, 출처.
- **근거 보기** 를 펼친다.
- 대본: "예상 혼잡은 실시간이 아니라 생활인구와 지하철 승하차 통계로 계산한 예상이에요. 근거와 기준 시각을 항상 같이 보여 줍니다.
  근거가 없으면 '정보 부족'이라고 그대로 말해요."

### 6. 지도 (약 20초)

- 뒤로 → **지도로 보기**. 마커 5개와 방문 순서 선, 아래 목록. 목록에서 광안리를 누르면 지도가 그 마커로 간다.
- 대본: "선은 방문 순서만 잇고 실제 도로 경로는 아니라고 지도에 밝혀 둡니다."

### 7. 되돌리기 (약 10초)

- 타임라인으로 돌아와 오른쪽 위 **되돌리기** → 오륙도가 빠지고 "직전 편집을 되돌렸어요".
- 대본: "방금 한 편집은 한 단계 되돌릴 수 있어요."

## 문제가 생기면

| 상황 | 대처 |
| --- | --- |
| 용두산이 14:45 에 들어감 | `data/crowd/` 파일이 없거나 백엔드를 그 전에 켰다. 파일을 확인하고 백엔드를 다시 켠 뒤 처음부터 |
| 경유지 후보가 없음 | 우회를 30분으로. TMAP 실측 값이면 후보가 달라질 수 있다(추정이 더 길게 잡힌다) |
| 지도가 안 뜸 | 지도 JS 키 허용 도메인에 `localhost:5173` 확인. 녹화 마지막 장면은 타임라인으로 대신한다 |
| 한 줄 해석이 실패 | 날짜·시간·이동을 직접 고른다(실패하면 입력 칸으로 바로 이어진다) |
| '다시 선택 필요' 카드 | 카카오 장소를 담은 뒤 새로고침하면 이름이 사라진다(D6). 새로고침하지 않는다 |

## 확인 방법(개발자)

장면 3·4의 값은 백엔드에서 직접 재현할 수 있다. 경로 키를 비우면 녹화와 같은 '추정' 값이 나온다.

```bash
cd backend
TMAP_API_KEY= ODSAY_API_KEY= uv run python - <<'PY'
from fastapi.testclient import TestClient
from app.main import create_app
c = TestClient(create_app()); c.__enter__()
t = c.post("/api/trips", json={"dates": {"start": "2026-12-05", "end": "2026-12-05"}, "dayStart": "10:00", "dayEnd": "21:00", "mode": "TRANSIT"}).json()
def fx(pid, s, e): return {"clientId": pid, "place": {"placeId": pid}, "dayNo": 1, "fixedWindow": {"dayNo": 1, "start": s, "end": e}}
sel = [fx("126658", "10:00", "11:00"), fx("126078", "13:00", "14:00"), {"clientId": "126121", "place": {"placeId": "126121"}, "stayMin": 60}, fx("130166", "17:00", "18:00")]
r = c.post(f"/api/trips/{t['tripId']}/schedule", json={"initial": {"policy": "FIRST_FEASIBLE", "selections": sel}}).json()
blocks = r["days"][0]["blocks"]
print([(b["arriveAt"], b["place"]["name"]) for b in blocks])
w = c.post(f"/api/trips/{t['tripId']}/waypoints/suggest", json={"fromBlockId": blocks[0]["id"], "toBlockId": blocks[1]["id"], "thresholdMin": 30}).json()
print([(x["place"]["name"], x["detourMin"]) for x in w["candidates"]])
PY
```
